# 抖音目录组稿与发布工具：技术方案讨论稿 v0.2

更新日期：2026-10-12。这份文档记录开发前的方案；当前桌面任务管理、预览和迁移已实现，最新运行方式见 README.md，验收范围见 validation-v0.1.md。真实账号协议发布尚未验证。

## 已确认范围

- 个人使用，Windows 与 macOS 都能运行；一次只在一台电脑上运行。
- 配置可导出、导入另一台电脑，数据可迁移；无需两台电脑同时联网协作。
- 第一版只做抖音图文，支持多个账号。
- 每个新建任务选择发布账号、文本文件夹与图片文件夹；不同任务独立保存目录与参数，业务流程相同。
- 抖音图片独立组成图集，文本独立作为文案，不采用图片和正文穿插的编辑方式。
- 第一版随机选图；名称、关键词等匹配后续预留。
- 用户可设置发布条数、发布间隔和定时开始时间。
- 每条图文默认随机配 1 张图片，可在当前任务改成多张；该批次所有图文使用同一个数量设置。
- 面向不懂技术的使用者，普通操作使用表单，不要求编写规则、JSON 或 Markdown。
- 优先 Node.js；希望采用 HTTP 协议发布，避免依赖模拟页面点击。
- 用户提供参考仓库：https://github.com/cv-cat/DouYin_Spider 。

## 推荐产品形态与技术栈

采用 Electron 桌面应用：直接选择本机目录，读取文件、展示组稿预览、管理账号、发布任务和配置迁移。Windows 和 Mac 各自安装运行。

| 模块 | 建议技术 | 目的 |
|---|---|---|
| 桌面程序 | Electron | 原生目录选择、文件读取、账号授权窗口、导入导出 |
| 界面 | React、TypeScript、Vite、Ant Design | 账号配置、规则、图文预览、发布记录 |
| 业务与执行 | Node.js、TypeScript | 扫描目录、解析文本、选图、执行任务与协议适配 |
| 数据 | SQLite、Drizzle | 本机账号元信息、任务、素材使用与成功台账 |
| 配置校验 | Zod、版本化 JSON | 校验规则、兼容迁移版本 |
| 文本 | TXT 优先；纯文本兼容入口，其他格式按实际需求增加 | 整文件读取为文案，不要求特定标题或标记格式 |
| 图片 | Sharp | 读取图片尺寸、规格校验；需要时转换格式 |
| 发布 | 独立 Node.js HTTP 协议适配器，先做可行性验证 | 将平台登录、上传和提交变化限制在一个模块 |
| 可选授权辅助 | 独立浏览器账号环境 | 仅在登录或人工验证需要时使用；不作为模拟点击发布主路线 |

React 只处理界面，通过受控 preload IPC 调用 Node 模块；目录读取、凭据和发布执行留在主进程或工作进程。无需初版共享服务器、云存储或多机调度。

依据：[Electron 原生文件和目录选择](https://www.electronjs.org/docs/latest/api/dialog)、[Electron 进程安全建议](https://www.electronjs.org/docs/latest/tutorial/security)。

## 参考仓库调研结果

已查看当前 master 的 README、`quick_publish.py`、`dy_apis/douyin_creator_api.py` 等源码。仓库确实含有图集上传和提交实现，不仅是采集器。

- 图集链路覆盖上传授权、申请上传、上传图片、完成上传、组装内容和提交。
- 快速发布示例调用 `post_images`；支持扫码、短信或 Cookie 登录入口。
- 主体是 Python。不能因为部分功能调用 Node，就把它视为现成 Node.js 发布库。
- 快速发布脚本明确登录凭据只存在本次进程中，不保存扫码或短信登录状态。
- 示例默认仅自己可见，仍然属于实际提交，不等于离线预览或草稿。
- 属于创作者网页内部接口方案，不能与面向第三方申请权限的官方开放 API 混为一谈。
- 登录和发布还涉及会话绑定、请求签名与上传授权。不能假定用 Node `fetch` 替换几个请求即可等价运行。
- 调研时未发现明确的 LICENSE/COPYING；README 的学习研究声明不等于可自由复用、分发许可。此项目先作为技术参考，不直接复制为可分发底座。

来源：[仓库说明](https://github.com/cv-cat/DouYin_Spider)、[快速发布源码](https://github.com/cv-cat/DouYin_Spider/blob/master/quick_publish.py)、[创作者接口源码](https://github.com/cv-cat/DouYin_Spider/blob/master/dy_apis/douyin_creator_api.py)。

建议先验证最小 Node.js 协议链路：账号身份确认、会话恢复、图片上传、单条图文提交、结果核对。登录会话、平台响应和跨操作系统差异都需要实际验证。这里只做调研，不执行参考项目，不发送真实发布请求。

## 使用流程

```mermaid
flowchart LR
  A[选择账号及其目录] --> B[扫描文本]
  B --> C[解析标题与正文]
  C --> D[随机选图]
  D --> E[生成固定图文任务]
  E --> F[确认批次与排期]
  F --> G[协议上传与发布]
  G --> H[记录结果与素材使用情况]
```

“一个任务”在用户界面上表示一批图文发布。该任务选择一个目标账号、两类素材目录、发布总条数、每条图片数、间隔和开始时间；内部保存每条图文的子任务及结果。不同任务互不覆盖设置。账号可记住最近使用目录，用户新建任务时仍可更换。任务设置可复制，再调整账号或目录。

## 面向新手的配置与第一版规则

普通用户操作：添加账号并登录，新建任务时选择目标账号、文案文件夹与图片文件夹，每条图片数默认 1，填写发布条数、间隔和开始时间，查看预览后创建任务。无需编写规则。界面提供“复制任务”，目标任务可重新选账号和目录。

图片和文案分别展示：左侧为图片图集，右侧为独立文案。默认完整读取文本；不自动把首行拆成标题，不把图片插入文案。需要标题时可以展开可选设置，手动填写或选择文件名作为标题，不让使用者改造所有文件。

当前建议默认值与确认情况如下：

| 配置项 | 建议 |
|---|---|
| 文本单位 | 建议一个文本文件对应一条图文；整文件作为文案 |
| 标题 | 可选设置，不默认拆分文案首行 |
| 随机配图 | 已确认随机模式；每条默认 1 张，可在任务中调整，整个批次使用该数量 |
| 图片顺序 | 保存生成时顺序；首图作为默认封面候选，可在预览调整 |
| 文本去重 | 默认同账号不自动重复；跨账号可分别使用 |
| 图片复用 | 建议可跨稿复用；可增加账号内避免重复的选项 |
| 发布数量 | 已确认按任务设置，这批任务创建指定数量的图文；不作为账号全局设置 |
| 开始时间 | 已确认支持定时；提供立即开始与指定日期时间 |
| 发布间隔 | 已确认可设置；建议上一篇确认提交成功后等待指定分钟/小时 |
| 任务创建 | 展示批次和内容预览，确认后按计划自动执行，无需每篇重新点击 |
| 原始素材 | 默认保留，以台账记录使用，不默认删除或移动 |

随机选图只在生成任务时发生。单条图文内不重复选同一图片。是否允许跨稿复用暂按允许设计，待用户明确；若选择不复用，则生成前校验整个批次所需图片数量。

生成任务时固定标题、正文、图片清单、顺序、素材内容摘要与规则版本。随机只发生一次，失败重试沿用同一组图；文件在执行前发生变化时重新确认，不把同一任务变成另一份内容。

## 批次、间隔和定时语义

- “发多少篇”指计划任务数量，不是循环补取素材直到成功数量达到 N。
- 文本默认从未发布的文件中按文件名自然排序选取，预览显示本次选中哪些文件。
- 开始时间指第一篇最早开始上传的时间，不能承诺该时刻已公开展示。
- 间隔从上一篇确认提交成功后计算，不等待审核结束。例如 20:00 开始，20:02 提交成功，间隔 10 分钟，则第二篇最早 20:12 开始。
- 排期预览标注“预计最早开始”，上传、排队和人工验证可能顺延。同账号严格串行；初版全局串行时不同账号也可能排队。
- 创建前检查文案与图片是否够用；不足时明确提示缺少数量，不静默创建不完整批次。
- 应用重启或电脑休眠后恢复任务记录，错过的任务暂停等待用户选择继续，不连续追发。
- 继续批次时从当前时间重新计算剩余任务间隔。结果待确认的任务必须先核对，不能因恢复批次而重发。
- 表单提示“定时发布需要电脑开机、保持唤醒并运行程序”。单次定时批次不默认扩展为每天重复计划。
- 保存明确时区，默认 Asia/Shanghai；迁移后保留时间含义，不能随另一台电脑时区悄悄改变排期。

## 给其他平台预留

内部内容结构区分独立文案、可选标题和有序媒体列表。抖音适配器把它们映射为文案与图集。未来需要图文穿插的平台，可增加有序内容块与所见即所得编辑器；用户通过插图按钮操作，不要求学习标记语法。

平台适配器报告是否支持标题、图集、穿插排版、平台原生定时等能力，界面按能力显示表单。第一版只展示抖音需要的操作，配图匹配和高级规则保留扩展接口。

## 账号与发布状态

每个账号拥有独立的认证会话，发布前核对身份；同账号任务串行，初版全局并发先设为 1。是否需要浏览器及持久环境由协议验证结果决定，纯 HTTP 路线仍需保存、更新与验证账号会话。

无痕浏览器不是长期保存完整环境的方案。如需授权辅助，使用每账号专属持久目录，独立于日常浏览器。账号隔离不能保证平台不会触发验证。

任务至少区分待预览、待执行、上传中、提交中、等待人工、已提交待审核、已发布、失败、结果待确认。提交成功与公开可见分开记录。

上传失败不会消耗素材。最终提交后超时，不能直接重发：先核对平台是否已经接收；无法判断时保留“结果待确认”。只有明确成功才更新对应成功台账。已经选入待执行任务的文本先预占，避免连续生成多批时重复选入。

## 配置与数据迁移

| 导出内容 | 处理方式 |
|---|---|
| 配置 JSON | 账号逻辑 ID、名称、任务配置/模板、目录用途、规则、版本号；默认不含登录凭据 |
| 数据迁移包 | 规则、成功历史、素材摘要、任务快照；已执行记录保留，未完成任务导入后暂停 |
| 可选素材包 | 文本和图片、相对路径、文件清单与内容摘要 |
| 登录状态 | 默认新机器重新登录；用户若需要凭据迁移，另行设计并验证 |

目录采用“逻辑目录 ID + 相对文件路径”。例如账号 A 的文本目录在 Windows 绑定到 `D:\素材\账号A\文本`，导入 Mac 时重新选择 `/Users/me/素材/账号A/文本`。原绝对路径只作为提示，不作为可直接复用路径。

只迁移配置不会带走去重历史。要保持发布记录和避免重发，需要迁移成功台账。导入任务不立即自动发布；提交结果不确定的旧任务先核对。备份数据库时使用一致性快照，不复制正在写入的文件冒充完整备份。

认证资料保留在本机凭据存储。Electron 的本地加密依赖操作系统，不能直接把 Win/Mac 加密文件搬过去就当登录恢复成功。见 [Electron safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)。

## 开发顺序与智能体分工

1. 采用任务级的完整文本+独立图集、随机图片、数量/间隔/定时表单流程；每条默认 1 张图。
2. 优先验证 Node.js 图文协议适配的登录、会话保存、上传与结果核对；实际发布内容和可见范围单独明确后验证。
3. 固定任务结构、账号目录配置与 IPC/API 约定。
4. 界面智能体：账号目录、规则、图文预览、任务与导入导出界面。
5. 素材/规则智能体：扫描、完整文本解析、随机选图、固定任务、去重与批次排期。
6. 协议智能体：账号会话、上传、发布适配、结果核对和异常暂停。
7. 主智能体负责数据库/迁移整合、代码审查和验收。

验收重点：不会发错账号；文案不被自动拆分；随机重试不换图；间隔按确认提交计算；重启不追发；成功历史迁移后仍有效；跨系统目录可重新绑定；导入未完成任务不会意外发布。Windows 可在当前环境测试，Mac 需实际设备验收。
