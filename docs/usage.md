# 使用说明

## 登录账号

在“账号管理”添加一个便于识别的账号名称，点击打开账号窗口并正常登录抖音创作者中心。身份核实成功后，首次登录窗口会自动隐藏；也可手动点击“检查登录”。需要平台二次验证时，在账号窗口完成。

每个账号使用独立、持久的浏览器环境。关闭账号窗口会保留后台会话，程序重启后可再次核实登录状态。这种环境会保存登录数据，不是关闭后清空数据的无痕模式。已绑定账号与当前登录身份不一致时，切回原账号或新建一个账号配置。

## 准备素材

文案与图片分开选择，两类素材都支持文件夹、单个文件和多个文件。选择文件夹会扫描子目录；选择文件只读取明确选中的文件。同内容的不同文本文件分别算作一篇，允许再次使用其他任务或发布历史中的文案。

| 素材 | 当前规则 |
| --- | --- |
| 文案 | `.txt`、`.md`、`.text`，整文件读取为一篇，不解析 Markdown 排版 |
| 编码 | UTF-8，或带 BOM 的 UTF-16；其他编码请先另存为 UTF-8 |
| 文案大小 | 单文件最多 1 MiB；空文件和无效文件会被跳过并提示 |
| 图片 | JPEG、PNG、WebP；单张最多 50 MiB，解码像素最多 4000 万 |
| 正文 | 应用按 JavaScript 字符长度校验，最多 1000；表情等字符可能占多个单位 |
| 标题 | 默认不生成标题，可选用去掉扩展名的文件名，最多 20 个字符单位 |

图片作为图集，正文作为完整文案，二者不穿插。发布预览会提示超长正文或标题；修改源文件后重新生成预览，程序不会自动截断正文。损坏图片和符号链接等无效来源不会纳入可用素材。

## 创建图文批次

1. 选择发布账号，指定文案与图片来源。
2. 选择文案后，“本批发布条数”默认等于有效文案文件数量。可手动修改，单批为 1–1000 条，不能超过有效文案数。选择图片或再次扫描不会覆盖手动条数；重新选择文案会重新计算默认值。
3. 设置每条图片数量（默认 1，最多 35），选择是否允许图片在本批次重复使用。每条内部不会重复选择同一内容的图片；图片池按内容去重。如果本批次不允许复用，则需要足够图片分配给所有稿件。
4. 设置公开或仅自己可见、开始时间及发布间隔（至少 1 分钟）。界面排期使用北京时间。文案按文件名自然顺序取本批数量，图片随机选择。
5. 扫描素材并生成整批预览。逐条核对内容、图片和排期，确认保存，再点击“开始”。

一个任务代表一批稿件。不同账号或不同文件夹可新建不同任务，每个任务独立设置数量与图片数。确认的预览会固定文案和图片；发布前发现原文件被改动，会要求处理，避免实际内容与确认内容不同。失败后重试不会重新随机选图。

## 执行与异常处理

程序打开、电脑唤醒并联网时才执行任务；不会在应用退出、关机或休眠期间后台发布。恢复后查看任务状态，确认素材和登录情况，再手动继续。定时开始时间是本机调度时间，实际提交可能受上传、账号间隔和平台响应影响。

同一账号的多个任务共用发布间隔。可暂停、继续或取消任务。上传阶段中断不会提交作品；最终提交已发出但回执无法确定时，会标记为“待核对”并阻止该账号继续发帖。

遇到待核对的稿件，先打开抖音作品列表，确认是否创建作品，再在任务详情选择“已发布”或“未发布”。这项处理防止未知提交被盲目重试，不限制再次使用相同素材。程序记录提交回执，平台审核与最终可见状态以抖音显示为准。

## 数据迁移

在“数据与记录”中选择导出或备份：

| 类型 | 包含内容 |
| --- | --- |
| 导出配置 | 账号名称、任务规则、来源路径提示，不含发布历史；导入后可复制任务创建新任务 |
| 备份任务数据 | 稿件快照、任务状态和发布记录，可恢复检查 |

两种导出都不包含素材原文件、登录凭据或浏览器环境。换电脑时单独复制素材目录，在新电脑导入数据、重新登录账号并重绑定本机素材路径。Windows 与 macOS 路径不同，原路径只作提示，程序会核对迁移任务的素材内容。导入不会自动开始发布。

重复导入遇到同名账号或任务时，程序会显示替换范围。选择“备份并替换”会先在本机应用数据目录的 `migration-backups` 保存当前工作空间，再导入；取消则保留当前数据。

通过“数据与记录”可打开本机数据目录。请使用应用内导入导出迁移，避免同步正在使用的 SQLite 数据库或跨系统复制浏览器环境。导出文件可能包含文案、发布记录与本机路径，上传 GitHub 时不要将个人备份、数据库或账号环境加入仓库。
